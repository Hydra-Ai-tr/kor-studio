Kor Studio 0.8.0 keeps the whole training run on the graphics card and trains much larger text models: an 85-million-parameter model on a 4 GB laptop GPU.

**Video:** [English](https://github.com/Hydra-Ai-tr/kor-studio/releases/download/v0.8.0/kor-studio-v0.8-en.mp4) · [Türkçe](https://github.com/Hydra-Ai-tr/kor-studio/releases/download/v0.8.0/kor-studio-v0.8-tr.mp4)

## New

- **Weights, gradients and the optimizer stay on the GPU.** In 0.7 every step sent all weights to the card and brought the gradients back, and AdamW ran on the CPU. Now the weights, gradients and AdamW or SGD moments live on the card for the whole run. Gradient clipping and the embedding gradients are computed there too, and each step only sends tokens. The CPU copy is refreshed every 20 seconds and whenever tests, checkpoints, the best weights, a pause or a plugin need it. The log says *weights, gradients and optimizer stay on the GPU*. If the card fails during training, Kor picks up on the CPU from the last weights the card handed over.
- **Batches that don't fit are split.** If a batch does not fit in the GPU memory, it runs in several passes and the gradients add up on the card, so the result is the same as one pass.
- **Bigger models.** The automatic plan now uses the GPU memory: with *Train on the graphics card* turned on it picks models of about 14M, 38M, 86M or 200M parameters, if they fit the card, the RAM and the amount of text. Manual design allows up to 48 layers, 32 heads and a context of 2048 tokens for text models on the GPU. Larger models get a lower learning rate, about 32k tokens per step and a warmup.
- **Large text files with less memory.** Text is read straight into memory without a copy per character, subwords are learned from samples of the text, and question/answer detection only reads the start of the file. If a file does not fit, Kor says so instead of crashing.
- **Faster tokenizer.** A byte trie with longest match. `kor-cli selftest` checks it against a simple reference version.
- **Checkpoints scale with the model.** The time between checkpoints is at least 20 times what the last save took, so large models don't spend their time saving.
- The GPU lines in the training log are now translated.

## Checked

All on an RTX 3050 Ti Laptop GPU (4 GB) with an i5-12500H:

- An **85,567,565-parameter** model (768 wide, 12 layers, 12 heads, 512 tokens of context) trains on the 4 GB card. Its gradients match the CPU within 1e-06.
- Splitting a batch into passes of 3 sequences gives the same gradients as the CPU within 6e-07.
- Four steps with the weights and the optimizer on the card match the CPU: SGD within 6.6e-07; AdamW within a thousandth of one update.
- Stopping and resuming a GPU run gives exactly the same weights as an uninterrupted run (difference 0).
- One training step of the 4.85M-parameter model takes 127 ms on the GPU, the same as in 0.7.1.

## Download

- `kor-studio-0.8.0-setup.exe`: the installer.
- `kor-studio-0.8.0-windows-x64.zip`: the portable version; extract it and run `kor-studio.exe`.
- `kor-studio-0.8.0-linux-x64.tar.gz`: Linux.

Windows 10 or newer with a 64-bit CPU is required. Python 3 is only needed for plugins and skills. The programs are not code-signed yet, so Windows SmartScreen may ask for confirmation (*More info* → *Run anyway*).

## Known limitations

- Text generation, question tests and chat still run on the CPU. For models with tens of millions of parameters they are slow, and on the 85M model they took most of the time of a short run. GPU generation is planned.
- With an average of the weights (EMA) the optimizer runs on the CPU, as in 0.7.1. LoRA fine-tuning sends only its large matrix products to the card.
- Large models need a lot of text: the automatic plan only picks 86M parameters for 500 million tokens or more, and 200M for a billion or more.
- Tested on an NVIDIA laptop GPU. AMD and Intel cards with OpenCL should work and are checked against the CPU before training, but are untested.
- The releases are not code-signed. On PCs with Smart App Control turned on, Windows may refuse to run them.
