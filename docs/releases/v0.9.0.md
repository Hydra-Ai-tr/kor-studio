Kor Studio 0.9.0 opens ready-made GGUF models (Llama, Qwen2 and their relatives such as SmolLM and Mistral), chats with them on the CPU and fine-tunes them with LoRA on a frozen 4-bit base. Models you train yourself get a modern Llama-style architecture, text generation on the GPU and a name.

**Video:** [English](https://github.com/Hydra-Ai-tr/kor-studio/releases/download/v0.9.0/kor-studio-v0.9-en.mp4) · [Türkçe](https://github.com/Hydra-Ai-tr/kor-studio/releases/download/v0.9.0/kor-studio-v0.9-tr.mp4)

## New

- **GGUF models.** Open a `.gguf` file from Hugging Face on the chat page, or use `kor-cli gguf info|chat|generate model.gguf`. Supported: the `llama` and `qwen2` architectures, which include Llama 2/3, Mistral, SmolLM and Qwen2/2.5. The weight types are F32, F16, BF16, Q4_0, Q4_1, Q5_0, Q5_1, Q8_0, Q2_K, Q3_K, Q4_K, Q5_K and Q6_K. Weights stay quantized in memory, and the file is memory-mapped, so a model opens in a fraction of a second. Both tokenizer kinds are built in: byte-level BPE (GPT-2, Llama 3, Qwen2 and SmolLM rules) and SentencePiece. The chat format (ChatML, Llama 3, Mistral, Phi-3, Zephyr, Gemma) is detected from the model's own template, and a system prompt can be set. On CPUs with AVX2 a faster build of the decoding code is picked at run time.
- **LoRA fine-tuning of GGUF models.** The base model stays 4-bit and frozen, and only small A and B matrices are trained on the attention layers, plus the feed-forward layers with `--mlp`. In dialogue data only the answers are trained. On the chat page, the *Fine-tuning (LoRA)* card shows the loss curve while it trains. You can also use `kor-cli gguf lora model.gguf data.txt`. Adapters are saved as llama.cpp-compatible `.gguf` files and can be loaded with `--lora` in `gguf chat` and `serve`.
- **API for GGUF models.** `kor-cli serve model.gguf` offers the model through the OpenAI-compatible API, with the model's own chat format.
- **Modern architecture for your own models.** New text models use RMSNorm, rotary positions (RoPE) and SwiGLU, like Llama, on the CPU and on the GPU. The old GPT-2 layout is still available with `--arch classic` or in the model designer, and older `.kor` models load as before.
- **Text generation on the GPU.** Generation, chat and `serve` can keep the weights and the key/value cache on the graphics card (`--gpu`, or the switch on the chat page). Any GPU error switches back to the CPU.
- **Better sampling.** Top-k, top-p and a repeat penalty, in the app, `generate`, `serve` and `gguf`.
- **Gradient checkpointing.** With `--recompute`, the blocks run again in the backward pass instead of keeping their activations. This uses less memory, on the CPU and on the GPU, and gives exactly the same gradients.
- **Name your model.** `--name` and `--maker`, or the fields in the app, store a name in the model. With dialogue data the model also learns to answer "What is your name?" with it.

## Checked

`kor-cli selftest --quick` and `kor-cli gpu --quick`, on an i5-12500H with an RTX 3050 Ti Laptop GPU:

- A Kor model written to GGUF (qwen2 and llama layouts, F32) gives the same loss in the GGUF engine, 4.02770 against 4.02770, and the same greedy text. As Q8_0 it gives 4.02556.
- The GGUF LoRA gradients match finite differences (worst relative error 0.0042). Saving and loading an adapter gives the same loss (3.92829).
- The modern architecture passes the gradient checks (worst relative error 0.0114), and on the GPU its text generation matches the CPU: 0 of 40 greedy tokens differ.
- Recomputing the blocks gives the same loss and gradients (largest difference 0).
- Three real models from Hugging Face open and answer coherently, on the CPU alone (8 threads, 100–120 tokens):

  | Model | Architecture, chat format | Speed |
  |---|---|---|
  | SmolLM2-135M-Instruct Q4_K_M (101 MB) | llama, ChatML | 51–60 tokens/s |
  | Qwen2.5-0.5B-Instruct Q4_K_M (469 MB) | qwen2, ChatML | 15–16 tokens/s |
  | Llama-3.2-1B-Instruct Q4_K_M (770 MB) | llama, Llama 3 | 6–7 tokens/s |

- For all three, the token ids of 14 hard texts (Turkish, Russian, numbers, spaces and tabs, code, emoji, URLs) are the same as with the official Hugging Face tokenizer.
- Llama-3.2-1B's perplexity on this README falls as the context grows (48.7 with 128 tokens, 26.6 with 512, 20.2 with 2048), so the rotary positions work over long contexts.
- A 4-step LoRA run on SmolLM2 saves a 3.7 MB adapter, which loads in `gguf chat`.

## Known limitations

- GGUF models run on the CPU only, and models of 1B parameters and more are slow (about 6 tokens per second for Llama-3.2-1B; llama.cpp is several times faster, because it multiplies the quantized weights directly). Other architectures (Phi, Gemma, mixture-of-experts models) and models with RoPE scaling are not supported yet and are refused with a message.
- Real files were tested for the formats above (Q4_K, Q5_0, Q6_K, Q8_0) and for BPE tokenizers. The other weight types and SentencePiece were checked with files written by the self-test.
- LoRA fine-tuning of GGUF models runs on the CPU and is slow for models above a few hundred million parameters.
- The releases are not code-signed. On PCs with Smart App Control turned on, Windows may refuse to run them.
